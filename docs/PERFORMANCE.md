# 성능 보고서 — v1.1.0 대비 v1.2.0

모든 수치는 아래 환경에서 실제로 측정한 값입니다. 측정하지 않은 항목은 "미측정"으로 적었습니다.

## 1. 측정 환경과 방법

| 항목 | 내용 |
|---|---|
| 장비 | GitHub Actions `ubuntu-24.04` 표준 러너 1대 — Intel Xeon 6975P-C, 4 vCPU, 메모리 15.7 GB |
| 그래픽 | **GPU 없음**: Xvfb 1920×1080 가상 화면 + Mesa llvmpipe(소프트웨어 렌더링). 실제 PC 의 GPU 성능과 다릅니다 |
| 비교 대상 | 기준 `v1.1.0-build.96` AppImage(릴리스 파일, SHA256 확인) ↔ 새 버전 dev-1.2 커밋 `9dbfd6c` AppImage. **같은 러너에서 연이어** 측정(2026-11-28 05:54 UTC 시작, perf.yml run 46112638131) |
| 도구 | `tools/perf_run.py` — CPU·메모리는 `/proc` 에서 프로세스 트리 전체(2 s 간격), 창 표시 시각은 `xdotool`, 프레임 수·ACACT 계산 시간·화면 전환 시간은 v1.2 의 `ML_PERF=1` 로그 |
| CPU % | 100 % = 코어 1개. 4 vCPU 이므로 최대 400 % |
| 시나리오 | ① 시작 3회(첫 번째는 AppImage 첫 실행) ② 대기(기체 없음) 90 s ③ 내장 데모 3기 자동 비행 + ACACT 240 s ④ (v1.2 만) 같은 데모에서 STANDARD/ADVANCED 10 s 마다 전환 120 s |

## 2. 결과

| 항목 | v1.1.0 | v1.2.0 | 차이 |
|---|---|---|---|
| 창 표시까지 (첫 실행 / 2·3회) | 3.72 s / 0.93 s | 1.43 s / 0.93 s | 다시 실행할 때는 같음 |
| 조작 가능(콘솔 준비)까지 | 미측정(v1.1 에 계측 없음) | 3.13–3.24 s | — |
| 대기 CPU 평균 | 243 % | 178 % | **−27 %** |
| 대기 메모리(RSS) 평균 | 389 MB | 387 MB | 같음 |
| 데모 3기 CPU 평균 / p95 / 최대 | 108 / 244 / 255 % | 96 / 243 / 255 % | 평균 −11 %, 최고치 같음 |
| 데모 3기 메모리 평균 / 최대 | 541 / 545 MB | 506 / 518 MB | −6 % |
| ACACT 개입 (같은 데모) | 2 회 | 2 회 | 같음 |
| 화면 프레임(대기) | 미측정 | 60.0 fps | — |
| 화면 프레임(데모 3기, 소프트웨어 렌더링) | 미측정 | 평균 25.2, 최저 10.0 fps | GPU 없는 환경 값 |
| ACACT 1회 계산 시간(20 Hz 주기 50 ms) | 미측정 | 평균 1.7 ms, 최대 19.9 ms | 주기 안 |
| 화면 모드 전환 → 다음 프레임 | 미측정 | 평균 18.9 ms, 최대 39 ms | — |

해석:
* v1.2.0 은 같은 조건에서 CPU·메모리를 v1.1.0 보다 더 쓰지 않았습니다(대기 CPU 는 줄었음). 대기 CPU 가 2 코어 이상인 것은 두 버전 모두 소프트웨어 렌더링으로 지도를 계속 그리기 때문으로 보이며, GPU 가 있는 PC 에서는 다를 것입니다(미측정).
* 데모 프레임 25 fps(최저 10 fps)는 GPU 없는 러너 값입니다. 실제 노트북·데스크톱 값이 아닙니다.
* 성능 모드(자동·경량·균형·고품질)별 측정은 하지 않았습니다. 기본값 "자동"으로만 측정했습니다.

## 3. 장시간 시험

| 항목 | 값 |
|---|---|
| 대상 | dev-1.2 커밋 `347032a` AppImage(v1.2 개발 중 빌드 — 이후 커밋의 화면·보고서 수정, 지형 기반 AGL 추적은 들어 있지 않음) |
| 장비 | GitHub `ubuntu-24.04` 러너(AMD EPYC 9V74, 4 vCPU, 16 GB), Xvfb + llvmpipe, perf.yml run 46105218519 |
| 내용 | 내장 데모 3기 자동 비행 + ACACT 를 끝나면 다시 시작(반복 재생), 30 s 마다 CPU·메모리 |
| **실제 시간** | **4 시간 30 분 23 초**(2026-11-28 03:57–08:29 UTC). 8 시간은 하지 않았습니다(GitHub 작업 한도 6 시간) |
| 결과 | 끝까지 실행 중(멈춤·종료 없음), 데모 비행 150 회 |
| CPU | 평균 206 %, p95 271 %, 첫 1 시간 평균 198 % → 마지막 1 시간 210 % |
| 메모리(RSS) | 시작 561 MB, 첫 1 시간 평균 552 MB → **마지막 1 시간 평균 637 MB**, 최대 682 MB(4 시간 9 분) |
| ACACT 1회 계산 시간 | 평균 2.7 ms, 최대 254.6 ms(1회성 지연 — 20 Hz 주기 50 ms 를 넘은 순간이 있음) |
| 프레임 수 | 이 빌드는 프레임 계측 결함(0 으로 기록)이 있어 **미측정** |

**판단**: 4.5 시간 동안 메모리가 **약 85 MB(시간당 약 19 MB) 늘었고 끝까지 평탄해지지 않았습니다.** 경고 이력(300개)·이벤트 로그(400개)는 상한이 있어 원인이 아닌 것으로 보이며, 원인은 찾지 못했습니다(가드 기록·지도 궤적·QML 캐시 등 후보). 같은 속도면 8 시간 운용에서 약 720 MB 로 16 GB PC 에서는 문제가 없겠지만 **미해결 항목**으로 둡니다. ACACT 계산이 한 번 254 ms 까지 늦어진 것도 원인 미확인입니다(GPU 없는 공유 러너의 부하 가능성).

## 4. 측정하지 않은 것

* 실제 GPU 가 있는 Windows 11 / Ubuntu PC, 저사양 노트북
* GPU 사용률, 전력
* 기체 4대 이상, 실제 텔레메트리 모뎀 지연
* 성능 모드별 차이
* 8 시간 운용(GitHub 러너 작업 한도 6 시간 — 위 장시간 시험의 실제 시간 참고)
